# Work-aware book discovery and library search

The anonymous web uses Open Library's work IDs for global discovery. It then searches the selected library's own catalog. No private item feed or copy counts are required.

## Discovery

- Free text combines Open Library text, title-specific, and title/author-field searches with Google Books. Open Library results retain durable `v1:openlibrary:OL…W` keys; Google results retain their ISBN/source identities. A successful source does not suppress the other source's results.
- Each request reads up to 40 raw records per query/source and retains the relevant candidates (up to 160), rather than truncating to ten records before grouping. `nextOffset` continues upstream pagination. The UI initially shows five presentation groups; **Show more books** reveals loaded groups, then fetches the next page. Search text and paging state stay in bounded same-tab memory.
- Result cards group records that share an Open Library work ID, and also records with different work IDs when they have the same normalised title, the same volume/part statement and the same non-empty author set (case, punctuation, "Last, First", roles, dates, initials and author order are ignored; only Latin accents are folded; Hindi/Tamil vowel signs and the "+"/"#" in titles such as "Let Us C++" are kept). The owner approved this relaxation for display grouping on 2026-11-11: Open Library holds duplicate work records for one book ("The Alchemist" by Paulo Coelho appears as three works), and duplicate cards were judged unacceptable. One obvious author typo is tolerated ("Coello" for "Coelho"): only for an identical title and volume that is not a generic title ("Poems", "Collected Works", "Poetical Works", school subjects such as "Mathematics"…), the same number of authors and name tokens, every token equal except one that is at least five letters in both, starts with the same letter and is within one edit, with at least one equal full name of four or more letters (initials alone, as in "R. D. Sharma" / "R. D. Sarma", are not enough), and only when the records' known languages do not conflict. Titles that differ only by a leading English article ("The Great Gatsby" / "Great Gatsby", "A Suitable Boy" / "Suitable Boy") share a card only when the author sets are exactly equal (never together with the typo allowance), the volume statements match, the known languages do not conflict and the article is not the whole title; a generic remainder by the same author ("The Poems" / "Poems") shares a card as an exact generic title does. Other languages' articles are not stripped. Titles are never otherwise fuzzy-matched. Records with different known languages share a card only on an exact title and author match, and their rows then name the language. Records without a work ID or author keep the earlier rules (an author-less record joins only the one attributed card with its title). Different authors, different volumes or parts, adaptations, abridgements, study guides and box sets (different titles) stay separate.
- A card that spans several work IDs is labelled **View n records** and says "The source has more than one record with this title and author." Most such cards are one book listed more than once (three Open Library works for Coelho's *The Alchemist*), but some are different books whose records carry the same title (Brian Herbert and Kevin J. Anderson's prequels recorded only as "Dune"). No field in the records separates the two reliably (years and covers do not), so the copy claims neither. Its rows show each record's own cover, year and edition count, are numbered as records, and never borrow another work's cover; volume titles are not invented. The card leads with the best-ranked record and shows the group's largest edition count, not a sum. Group keys use the `g2:` prefix (work ID of the best-ranked attributed record, or its title key) and never equal a record key; **Show more books** counts cards.
- Displayed titles (`server/services/searchRelevance.js`): a result keeps its work's own title when that title matches the query by itself, within the bounded spelling tolerance even on the strict pass ("the hobit" shows **The Hobbit**, not the transliterated alias "Hobiṭ"). Otherwise it is shown under the matched alternate or edition title, which is the title in the reader's words ("The Alchemist" for Coelho's work titled "O Alquimista"; "Fullmetal Alchemist 1" for "鋼の錬金術師 1"). Exception: when one matched title stands in for several works with different own titles in the same result set, it is a series or collective name, and those works show their own titles again, provided the own title is in the query's script. **Wings of Fire** therefore lists Kalam's book and then Tui T. Sutherland's *The Dragonet Prophecy*, *Darkstalker*, *The Lost Heir*… as separate cards. Duplicate records of one translated work ("O Alquimista" twice) are one own title, so they keep the alias. No public field was added. Known limits: records whose own title in Open Library is only the series name stay together on one card; Tolkien's *The Fellowship of the Ring* is matched only through its "The Lord of the Rings" edition titles and still shows under that title; the decision is made per result page.
- This is presentation grouping only, not a claim of work equivalence (`client/src/v2/searchGroups.ts`). Every row keeps its own `bookKey`, opens exactly that record, and runs its own ISBN set and availability lookup; ISBNs and availability are never combined across work IDs, and server identity and deduplication are unchanged. Rows are labelled by edition, publisher and year, then language, volume, edition count, format or ISBN where needed. Series subtitles remain visible; generic edition aliases do not overwrite an already matching specific title.
- Partial source failures retain successful results with a short notice. A failed next page leaves previous results and its retry action intact. Search results remain dependent on source indexing and availability; pagination is not a claim of exhaustive worldwide coverage.
- An ISBN or barcode retains its exact `v1:isbn:…` key. Open Library's ISBN endpoint adds its work relationship and language when known. Existing metadata sources remain an ISBN fallback.
- Ranking: text relevance filters (every significant query word, the bounded spelling rules, derivative works such as study guides excluded) and sets the main order. Open Library's reader-log and edition counts (log-scaled, capped) and each source's own result order then reorder matches; the cap keeps an exact title plus author above a popular book that merely contains the words. A title equal to the typed text, symbols included, gets a small bonus ("Let Us C" before "Let Us C++"). Records without these signals (Google Books, library catalogs) keep the text order. When several returned works are by one author whose name is the query, one extra paced request (`author=…&sort=readinglog`) adds that author's best-known works, which rank above books about the author. When strict matches come only from another edition's title (no record matches on its own title and authors), the first page also runs the bounded spelling pass and ranks both sets together. These signals are not part of the public book shape.
- `server/services/searchRanking.eval.test.js` replays 52 golden searches (`server/test/fixtures/search-ranking/`) offline and reports top-1/top-3 hits; run it directly for a per-query table. `tools/search-ranking/capture.mjs` refreshes the captured Open Library responses (paced, bounded).
- Different works are never merged for identity, ISBNs or availability, and never by fuzzy title comparison. The same title can legitimately refer to unrelated books, so display grouping also requires the same authors. Open Library can have duplicate or incorrect work records; display grouping hides duplicate cards but does not repair those relationships.
- Selecting a work resolves its details. Availability lazily reads at most 100 edition records from that work, preserving the language/format relationship of each ISBN. Unknown-language editions are not added as confirmed same-language alternatives. Audio, digital, and Braille editions are excluded from print expansion.
- Identical ISBN-10/13 representations normalize to one edition. The original scanned ISBN remains available independently of metadata enrichment.

## Selected library search

`searchLibraryBook` uses the existing scoped provider adapters. It starts an ISBN lookup and a title + primary author search together, then tries other known ISBNs (including ISBN-10 representations), title alone, and a known alternate title. Budgets are six ISBN queries, three text queries, six unique record inspections, and a 20-second catalog-search deadline. Metadata expansion has its own bounded request deadline.

Candidate records are reopened through their adapter when necessary. Stable record IDs deduplicate results. Branch and institution filtering remains inside each adapter. BiblioCommons supplies public candidate metadata directly, including titles, authors, languages, ISBNs, and a durable record URL. Koha detail parsing now retains author names for records without ISBNs.

The selected-library text picker uses Koha's public search in pages of 40, retaining branch filters and computing the next offset from the number of records actually returned. Title/author matches are ordered ahead of broader catalog keywords without dropping returned records. Responsibility statements nested inside Koha title links are excluded from the title. The captured Anna Centenary **Wings of Fire** fixture includes 18 independent records, including the autobiography and distinct novels; grouped cards preserve each record's separate holdings.

## Catalog covers and book information

Koha search ISBNs are accepted only from a cover container with the same biblionumber and title as the result. Conflicting identifiers are rejected. The catalog key remains unchanged. ISBN cover URLs use Open Library's `default=false` behavior so missing images show the app's placeholder rather than a blank cover.

Visible catalog cards and the book detail page request optional `/books/enrich` metadata after the catalog has rendered. Only server-resolved catalog keys are accepted. Open Library's ISBN edition and its linked work supply covers/descriptions; an exact-ISBN Google Books response fills gaps. Catalog title, authors, ISBN and publication data remain authoritative. Descriptive additions never supply an availability result or create a new work relationship. Missing ISBNs are not guessed from similar titles.

Enrichment is cached and coalesced by ISBN, bounded to ten seconds, and excluded from availability requests. Failures leave the catalog result usable. Grouped cards can fall back to another member's cover while each individual record retains its own ISBN and metadata. Book details reuse the existing About page without adding text to the library availability view.

The matcher tolerates punctuation, accents, author ordering, and initials for possible matches. It preserves meaningful title differences, volumes, adaptations, study guides, and revisions. An ISBN found through a keyword search must actually appear in the returned record before it counts as an exact match.

## Results and controls

- `exact_isbn`: the requested ISBN was verified by the adapter or candidate metadata.
- `verified_work`: a compatible known edition ISBN was verified. The response includes the matched ISBN.
- `possible_match`: title and author evidence without a known edition ISBN. The UI says **Check edition**; it never presents a confirmed availability claim or counts for this case.
- `in_catalog` needs catalog evidence, not copy counts. **Available now** still requires an explicit public circulation observation.
- `no_match` means this bounded search found no confirmed match. It does not claim that every edition is absent.
- `unknown` means the check could not complete reliably. A positive earlier match survives subsequent failures. A prior confirmed observation may be returned as explicitly stale.

The availability request accepts optional `editionScope: "work" | "exact"` and a three-letter `language`. Exact mode is only valid for ISBN keys. Scope and language are included in the stale-result cache key. The UI defaults to work search, offers **Only this ISBN** for scanned/typed ISBNs, and carries preferences through the library chooser using the book URL.

Open Library requests are cached for six hours, coalesced, and paced to at most one uncached request per second per server process with an identifying User-Agent. This is intended for user-driven discovery, not bulk indexing. Large or multi-instance deployments need a shared provider budget/cache.

Providers without a public text-search adapter still benefit from known-edition ISBN searches. Catalogs without a supported public lookup retain their existing external-catalog handoff. Provider errors, missing metadata, and catalog absence remain distinct.

## Validation

Run `npm test --workspace=server`, `npm run test:client`, `npm run typecheck:client`, and `npm run build` with Node 22. Tests cover grouped work keys, owner-approved cross-work cards and their guards (different authors, volumes, adaptations, languages, generic titles, author-typo limits), cold resolution, language and format filtering, ISBN variants, missing-ISBN recovery, reordered authors, conflicting titles, request budgets, deadlines, partial success, exact-mode isolation, UI controls, and grouped result limits.

For a live check, start `PORT=4195 node server/index.js` after building, open `/app/shelf`, search **Wings of Fire** in the shelf's search bar, open Kalam's work, and choose a supported library on the book page (Find my library). Repeat with **Harry Potter** to verify individual novels remain separate. Live catalog observations are time-sensitive and are not test fixtures.

References: [Open Library Search API](https://openlibrary.org/dev/docs/api/search), [Work and edition APIs](https://openlibrary.org/dev/docs/restful_api), [API usage guidelines](https://openlibrary.org/developers/api).

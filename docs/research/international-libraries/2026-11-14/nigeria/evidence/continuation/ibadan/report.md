# University of Ibadan catalog recovery — 15 November 2026

**Result: no additional verified library.** Ibadan remains a substantial candidate, but this continuation did not retrieve a genuine book search or holdings record. Failed access is not evidence of absent books or an origin outage.

The current [official guide](https://library.ui.edu.ng/library-guide) returned HTTP 200 at 07:02:13 UTC and explicitly names **University of Ibadan Integrated Library System (UIILS)** as its library management software. It gives **well over two million physical volumes across the university library system**: Kenneth Dike Library, Latunde Odeku Medical Library, and 26 faculty, departmental and institute libraries. These volumes include journals, dissertations, technical reports and monographs as well as books. The page is undated; this is neither a dated count of books nor proof of 28 separately accessible catalog deployments.

The [2023 official guide](https://ui.edu.ng/sites/default/files/2023-09/EDITED%20Library%20Guide%202023%201.pdf) publishes `http://ils.library.ui.edu.ng` for off-campus access and describes title, author, subject and keyword searches. Direct GETs for its robots file and homepage returned HTTP 403 with the explicit body **“No approved upstream IPv4 address”**, from an Envoy response. This establishes an environment routing failure; it does not establish that Ibadan's origin is down or forbids catalog use. An HTTPS robots request failed at the tunnel. The secondary web retrieval tool also could not access this hostname. The private `10.0.43.3:8080` address printed in the guide was not requested.

The current website continues to publish `http://41.184.122.87:8080/record/opac`. Earlier work recorded a timeout there; this continuation did not blindly repeat it. The current guide's apparent OPAC search field also cannot be treated as a search interface: the downloaded published JavaScript renders an input with only type, placeholder and styling, with no form, event handler or query endpoint. The component's only fetch call is an unrelated document chatbot. See `guide-search-widget-excerpt.txt` and the complete `guide-script.html`.

Further discovery found a university-authored KDLUI Android app in third-party indexes, but its Google Play listing was inaccessible through the web tool and exposed no alternative public catalog route. A [2018 conference account](https://swib.org/swib18/programme.html) describes a local UIILS service using Library of Congress subject-heading data for staff classification. It supplies no published public holdings API and was not treated as one. A union-catalog discovery lead did not establish Ibadan membership or holdings and was excluded.

The current guide requires university registration and an identification card for library use; regular non-university users must obtain exceptional permission for scholarship or research. These are physical-use and borrowing restrictions, separate from public catalog access. No origin automation permission was established. The current application robots parser was reviewed; its treatment of missing robots is not legal integration permission. No TLS, routing, authentication or robots restriction was bypassed.

**Integration implication:** retain Ibadan as a high-value blocked candidate. A reachable university-published UIILS endpoint or operator-authorized feed is needed before a title query, holdings proof and parser can be validated. Current official UIILS evidence should supersede an assumption that this is a Koha deployment; no existing app adapter was tested here.

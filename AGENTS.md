# Working on MyBookshelf web

MyBookshelf finds a book and checks whether a chosen library's public catalog
has it. This repository is the public copy of the web source; changes merged
upstream arrive here in the next sync. README.md has the commands and layout.

## Build, test, run

- Node 22, npm workspaces (`client`, `server`). `npm ci`, then `npm run dev`
  (app at http://localhost:5173) or `npm run build && npm start` (built site at
  http://localhost:3000).
- Checks: `npm run typecheck:client`, `npm run test:client`,
  `npm test --workspace=server`, `npm run build`, `npm run test:seo`,
  `node --test tools/deployment/*.test.mjs tools/catalog-hardening/*.test.mjs tools/accounts/*.test.mjs`,
  and Playwright (`npm run test:e2e --workspace=client`). Run the ones that
  cover what you changed; `.github/workflows/web.yml` is the full list.
- No keys or database are needed. Database suites skip unless
  `ACCOUNT_TEST_DATABASE_URL` / `CATALOG_TEST_DATABASE_URL` point at a
  disposable Postgres named `*_test`. A skipped suite is not a pass.
- `npm run build` also writes the static public pages (`tools/seo/build-pages.mjs`).
  Run `npm run test:seo` after it.

## Layout

- `client/src/v2/` the one-screen app: the shelf, with search, scan, the
  library pop-up and the side panel as overlays. Old `/app/search`,
  `/app/libraries` and `/app/settings` links redirect to it.
- `server/public-v2/` the anonymous API (`/api/v2`); `server/services/providers/`
  one adapter per catalog platform; `server/services/catalog-lookup/` the
  library check; `server/accounts/` and `server/catalog-store/` optional
  services, off until configured. The catalog store is separate from the
  account database.
- `server/data/`, `shared/`, `data/` versioned runtime and page data;
  `server/test/fixtures/` captured catalog pages for offline tests.

## Product rules

- A library check answers found, not found, or couldn't check, for the chosen
  library only. Never show copy counts, due dates, floors or shelf numbers.
- A failed or blocked check is unknown, never evidence that a book is missing.
- Keep edition and catalog identities apart: never merge works or editions
  from similar titles for identity, ISBNs or availability. Search cards may
  group same-title, same-author records for display only.
- Respect each catalog's access restrictions and robots.txt; keep requests
  paced and bounded, and identify with the app's user agent. Where a
  catalog's terms do not allow storing availability (BiblioCommons;
  `platforms` in `server/data/catalog-policies.json`, 23 November 2026),
  nothing about a book is stored or cached: every check is one live request.
- Provider keys stay server-side. Never put secrets in `VITE_` variables,
  source, tests, issues or logs. `.env.example` holds names only.
- Search text is never put in URLs, browser storage, platform logs or
  analytics. The server may keep it only in the anonymous operational log
  (no account ID, IP or device identifier), never linked to an account. A
  typed ISBN may appear in a book page's address: it is the book's identity.
  Google tag events go only through the allow list in `shared/google-tag.mjs`
  and never carry search text, book identity (a public page is sent by its address), the account or location.
- Location is used once and never stored.
- Respect reduced motion and keep everything usable by keyboard.
- Indian libraries are offered when finding a library only if
  `server/data/india-catalogs-listed.json` lists them. It is generated by
  `tools/catalog-hardening/library-status.mjs`; a listed library stays listed
  when a later check fails (unless blocked), and one is removed only through
  the file's `removed` list (id, reason, date). Unlisted IDs still resolve for
  readers who already chose them. US libraries are offered only if
  `server/data/us-catalogs-listed.json` lists them and its `removed` list
  (id, reason, date) does not. Libraries elsewhere are not affected.
- A catalog row with at least 80% of the title's words is a find, whatever
  its format or author, for every library. The card lists up to 10 matching
  rows, ranked (`server/services/libraryBookSearch.js`): the row showing the
  book's ISBN, then rows with the book's author; within each, exact main
  titles (before ":" or "/"), titles starting with the book's title, then
  other matches; within each, books and rows with no format, then e-books and
  audiobooks, then other formats; films and music last
  (`server/services/rowFormats.js`).
- `shared/seo-libraries.json` controls the reviewed library guides;
  `shared/seo-shelves.json` the generated library shelf and book pages.
- Never commit secrets, local environment values, account data or browser state.
